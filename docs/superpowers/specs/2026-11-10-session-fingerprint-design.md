# 会话级浏览器指纹画像设计

## 意图

让 UltraLightBrowser 的 macOS Edge 身份模式在浏览器可控制的信号上彼此一致，并在每次程序启动时生成新的会话级指纹画像。目标是减少长期稳定标识和明显的跨 API 矛盾，而不是承诺不可检测或匿名。

## 目标

- 启动时使用系统密码学随机源生成一次临时会话种子；种子只留在内存中，不写入配置、日志或磁盘。
- 同一程序进程的所有普通与隐私窗口共享一份画像；会话中同一 API 的结果保持稳定，重启后重新生成。
- macOS Edge 模式下，UA、Client Hints、`navigator.platform`、WebGL/WebGPU 信息、Worker/iframe 与画像中的设备类别保持一致。
- 优先保证画像字段彼此协调；Canvas、WebGL 像素和音频读回保持 WebView2 原生结果，不加入会话噪声。
- 自检页面展示当前画像、每次启动变化情况可人工复核，并明确哪些检测面无法被当前架构控制。

## 非目标与限制

- 不改写 IP、DNS、WebRTC 路由、TCP/IP、TLS、HTTP/2 或 QUIC 指纹。它们由网络路径、Windows 与 WebView2 运行时决定；现有 WARP/线路功能继续独立工作。
- 不声称能把 Windows 主机变成真实 macOS。系统字体、系统级语言/时区、物理屏幕与 GPU 渲染仍可能暴露宿主环境。
- 不采用每站点或每次 API 调用重新随机的策略；这会让同一页面读到互相矛盾的值，造成异常指纹。
- 不通过像素/波形噪声伪造 Canvas、WebGL 或音频结果；它们应维持真实渲染栈的可重复性。
- 不增加扩展、远程服务、账号或画像上传。

## 现状与约束

项目是 Windows 10/11 的 Win32/C++20 浏览器，网页由 Edge WebView2 渲染。已有 `macos-edge` 模式通过 DevTools Protocol 改写 UA 与 Client Hints，并由 `MacStealth.hpp` 注入 `navigator.platform`、WebGL/WebGPU 字符串、语音及 Worker 修补；伪装自检在 `SelfTestPage.hpp`。当前 GPU 字符串固定为 Apple M1，macOS 版本可配置，运行时读取 Edge 的品牌和版本。已有 UA 单元测试，但原生 WebView2 覆盖需 Windows 实机验证。

WebView2 不能可靠控制传输层指纹，也不能替换宿主字体、真实绘图栈或系统区域设置。DevTools 与 JavaScript shim 还可能被深度探测，因此功能应描述为“降低稳定性与信号冲突”，不宣传为完全隐身。默认 Windows 身份不应被改变。

## 考虑过的方案

1. **每次访问随机**：变化频繁，但单一会话内不连贯，容易暴露异常，舍弃。
2. **进程会话级随机画像（选定）**：启动时生成一份画像，所有标签一致，重启再换；兼顾连贯性与跨会话变化。
3. **少数固定画像池**：容易形成常见群体画像，但用户长期可能固定在同一画像，与本次希望随机生成的目标不符。

## 设计

- 将随机化挂在现有 `macos-edge` 身份模式下；默认 Windows 身份和网络配置不变。
- 进程启动后、创建首个 WebView 前生成临时种子。用 Windows `BCryptGenRandom` 等操作系统密码学随机源，不用时间戳、设备编号或 `std::rand`。种子不持久化。所有 WebViewManager 实例从一个进程级会话对象读取同一画像。
- 画像从四个成组配置中抽取：Apple M1/8、M2/8、M3/8、M4/10（GPU 标签/`navigator.hardwareConcurrency`）。所有标签共享同一配置。UA/浏览器主版本必须匹配实际 WebView2 运行时；平台、架构、设备类别、GPU 声明和硬件能力只允许取彼此兼容的组合。配置池有限，连续两次启动允许抽到同一项。不能凭空报告宿主不支持的 API 能力。
- Canvas/WebGL 像素与音频采样结果保持原生，不做噪声或伪造。它们可重复且可能成为宿主环境线索；自检明确列为未随机化/仍可识别面，不能将画像短摘要描述为完整指纹随机化。
- 维持现有 iframe、Dedicated/Service Worker 的统一覆盖逻辑；GPU 标签和 `hardwareConcurrency` 在所有目标中复用。SharedWorker 目前通过隐藏接口处理，不能假设它可注入。
- 更新身份自检页：显示画像标识（不可逆的短摘要，不显示种子）、当前会话稳定性结果、覆盖/未覆盖 API，以及不能控制的网络和主机信号说明。自检不得上传结果。
- 加入设置说明：画像在程序重启后变化；清除 Cookie/无痕窗口不会单独重置进程画像；深度检测可能识别 WebView2 或 shim。

## 成功标准

- 同一进程中新旧标签页、iframe 和受支持 Worker 对可覆盖 API 返回一致的画像值；字段组合与 WebView2 运行时保持一致。
- 重启后重新抽取画像，可能因有限画像池而重复；种子和画像摘要不写入配置、浏览记录或其他持久数据。
- UA 与 Client Hints 仍符合当前 Edge/WebView2 运行时版本；默认 Windows 身份完全不变。
- 自检区分“画像已协调”“保持原生结果”“架构无法控制”，不把网络侧或主机侧结论误报为已伪装。
- 无声称对浏览器指纹具有绝对随机性、不可检测性或匿名性的文案。

## 需要审阅的实现选择

本设计选择画像字段成组随机、渲染读回保持原生。理由是自洽优先：给绘制或音频读回加噪会令结果与实际渲染栈不符，还可能损害兼容性。当前 macOS Edge 模式把 WebGL 字符串写成 Apple M1，但 Windows WebView2 的像素渲染仍来自宿主 GPU；新自检必须显示这一限制。若要求完整模拟 Mac 的字体、GPU 栅格化和系统行为，当前 Windows/WebView2 架构无法做到。
